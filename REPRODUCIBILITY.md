# Уровни воспроизводимости

Команды выполняются из корня submission. Установка описана в [README](README.md).
Имеющиеся результаты не перезаписываются: для новых вычислений задавайте
отдельный каталог вывода.

Шесть уровней ниже различаются по тому, что именно проверяется. Смешивать их
не следует: пересчёт сохранённых чисел и повторение эксперимента — разные вещи.

## 1. Просмотр без вычислений

[PDF](docs/report/report.pdf), [результаты](RESULTS.md),
[приложения](docs/APPENDICES.md), [шесть видео](docs/VIDEOS.md).
Достаточно браузера, просмотрщика PDF и видеоплеера.

Копии медиафайлов внутри каталога отчёта сохранены как часть принятого
комплекта, и их содержимое побайтово совпадает с корневым. Git хранит
одинаковые объекты один раз. Таблицы CSV и рисунки сохранены без изменений;
PDF и пояснения отредактированы, научные результаты при этом не менялись.
В PDF есть одна ссылка — на главную страницу репозитория; локальные файлы
из него не запускаются.

## 2. Компактные числа и графики — чистый клон

```bash
python3 -B -m scripts.verify_submission
python3 -B -m scripts.reproduce_results --check
python3 -B -m scripts.reproduce_robustness --check
python3 -B -m cartpole.experiments.robustness_analysis --normalized results/robustness/normalized.json --check
python3 -B docs/report/scripts/check_report.py
.venv/bin/python -B -m scripts.reproduce_robustness --figures --output output-robustness
```

Первые пять команд используют только стандартную библиотеку: ни torch,
ни Drake не требуются. Проверка нормализованного набора сверяет его собственные
контрольные суммы — идентичности записей, огибающую метрик и научный хеш;
происхождение исходных архивов и пересчёт из сырых журналов при этом заново
не выполняются. Последняя команда требует Matplotlib и нового каталога вывода:
существующий каталог отвергается, а модуль независимо пересчитывает шесть CSV
и пять графиков PNG/SVG.

Основная серия, Stage 1 и confirmation пересчитываются из компактных
аудированных CSV. Независимой проверкой сырых журналов обучения это
не является. Отбор и подтверждение используют только 20 валидационных
состояний, а не три именованных сценария. Исторические отчёты остаются
снимками своего этапа.

## 3. Сборка отчёта

```bash
bash scripts/build_report.sh
```

Нужен XeLaTeX либо Tectonic и установленный Times New Roman в четырёх
начертаниях; это системные зависимости, в Python-окружение они не входят.
Автоматической подстановки другого шрифта в исходниках нет.

Текущая редакция PDF **собрана локально** движком XeLaTeX (TeX Live 2023)
с настоящим Times New Roman: 41 страница, шрифты встроены, все страницы
отрендерены и просмотрены. Русские шаблоны переносов при этой сборке активны, что само по себе меняет
разбиение строк; в этой редакции изменился и текст, поэтому вёрстку прежних
редакций она не воспроизводит.
Подробности редакций — в [инструкции к отчёту](docs/report/README.md);
контрольные суммы прежних и текущей редакций сохранены в
[PORTABILITY](docs/report/PORTABILITY.json).

## 4. Сохранённая политика

```bash
.venv/bin/python -B -m scripts.frozen_inference --load-check
.venv/bin/python -B -m scripts.evaluate_capsule --model SAC_seed0 --filter on
# Следующая команда действительно запускает 23 новых эпизода по 10 с:
.venv/bin/python -B -m scripts.evaluate_capsule --model SAC_seed0 --filter on --output output-sac0 --execute
```

Включены веса всех SAC и TQC для seeds 0/1/2, закреплённые привязками,
метаданными, историческими manifest и контрольными суммами. Загрузка проверяет
веса, библиотеки, научные исходники и 23 сохранённые пробы на модель.
Единственное уже проверенное исключение — известная пара контрольных сумм
конфигурации, различающихся только в реестре и только на пути inference.

На этой подготовке проверены загрузка и пробы на CPU; **новые эпизоды
не запускались**. Маршрутизация оценки проверена mock-тестом и планом, CUDA
заново не проверялась. Каждый запуск создаёт новый каталог вывода и скрытого
продолжения не поддерживает.

Классический контроллер и полная оценка контрольных точек используют исходный
runner:

```bash
.venv/bin/python -B -m scripts.evaluate --classical --filter on --workers 1 --output output-classical
# --execute добавляется только для сознательного запуска новых эпизодов.
```

Включён файл `tests/fixtures/swing_up_nominal.npz`, его контрольная сумма
закреплена в конфигурации. Загрузка модели — десериализация доверенного
артефакта, поэтому заменять ZIP посторонними файлами нельзя.
Inference-комплекты не содержат replay и runtime и **продолжить обучение
не позволяют**.

## 5. Повторить обучение — отдельный дорогой эксперимент

Научный runner и закреплённые конфигурации включены; запуск начинается с нуля,
seeds задаются явно. Ниже приведён пример одного исходного SAC-on — это
не автоматический запуск серии и не обещание побитового воспроизведения
стохастического обучения. Ограничение по времени играет роль защиты.

```bash
.venv/bin/python -B -m scripts.train plan --config sac_training_v2_on --seed 0
.venv/bin/python -B -m scripts.train init-session --session output-training/session.json --seconds 43200 --reserve-seconds 120
.venv/bin/python -B -m cartpole.experiments.cloud_guard --session output-training/session.json --phase main --max-seconds 42000 --output-dir output-training/guard -- .venv/bin/python -B -m scripts.train run --config sac_training_v2_on --seed 0 --session output-training/session.json --max-seconds 42000 --output output-training/sac0
```

Сессия ограничена только временем, без фиктивной цены, и срок не продлевается.
План проверен; новое обучение в этой подготовке не запускалось. Потребуется
существенный запас диска для новых буферов и контрольных точек. Использовать
inference-ZIP как начальные веса нельзя. В основной серии буфер рассчитан
на 100000 записей при 100000 переходов; вариант warmup5000 даёт 95000
обновлений, исходные варианты — 99872.
[Конфигурации основной серии](configs/cloud/), [Stage 1](configs/development/),
[confirmation](configs/confirmation/) — независимые исторические серии.
Для полноценного возобновления прежнего обучения нужны внешние runtime, replay
и идентичности, которых этот компактный комплект не содержит. Итоговый закрытый
набор не входит ни в одну команду.

## 6. Проверка сырых журналов и повторный рендер — внешние данные

В Git нет больших архивов review и recovery, сырых журналов и исходных
видеовходов. Происхождение сохраняют
[контрольные суммы серий](provenance/archives.json),
[robustness provenance](provenance/robustness.json) и
[принятый manifest медиафайлов](media/VIDEO_MANIFEST.json).
Для импорта robustness нужны внешние архивы вместе с их sidecar-файлами
и контрольными суммами:

```bash
python3 -B -m cartpole.experiments.robustness_analysis --help
.venv/bin/python -B -m cartpole.experiments.robustness_video --help
```

Точные параметры импорта перечислены в
[каноническом README](docs/assets/structured_robustness/README.md).
Рендер видео дополнительно требует внешних исторических эпизодов и анализа
confirmation — из нормализованных метрик или моделей они не восстанавливаются.
В этой подготовке проверка сырых журналов, рендер MP4 и rollout не повторялись,
и обозначать компактную проверку как проверку сырых данных нельзя.

Исторические manifest не переписаны под submission. Семь зависевших от
локальных путей Markdown-документов отчёта заменены явно производными
описаниями; исходные контрольные суммы, причины замены и новые суммы
перечислены в [PORTABILITY](docs/report/PORTABILITY.json).
Актуальный состав комплекта проверяется по [SHA256SUMS](provenance/SHA256SUMS).
